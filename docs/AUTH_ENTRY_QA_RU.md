# RULESHIFT 2.1: вход, профиль и публичный рейтинг

Дата проверки: 10 октября 2026. Ветка: feature/ruleshift-2-chaos-update. Protocol v8 сохранён.

## Локально реализовано

- До меню проверяется сессия. Первый визит показывает RULESHIFT и выбор Google / Email / Гость. До ответа сервера виден экран ожидания, а не главное меню.
- Гостевой выбор хранится в отдельном ключе ruleshift.entry-choice. Reload не требует повторного выбора. Ошибка проверки сессии не выдаётся за гостевой вход: доступны повторная попытка и явный выбор гостя.
- OAuth callback направляет в экран аккаунта. Автоматического повторного запуска OAuth нет.
- В профиле сохранены ник, цвет, локальный XP, достижения, статистика и вкладки. Раздел «Аккаунт и вход» содержит серверный ник, тип и привязанные способы входа, Google/email linking, logout и существующее удаление аккаунта с подтверждением.
- Logout отзывает сессию существующим API и возвращает на выбор входа. Существующая подписка Online на отзыв сессии сохранена.
- Google/email не требуют recovery codes. Ненастроенные провайдеры явно недоступны.
- Публичный Leaderboard содержит реальные строки API, количество игр, рейтинг, победы/поражения/ничьи, процент побед, серии и фильтры. Формы входа, привязки и редактирования удалены. Гостя направляют в профиль.
- Регистрация новых Passkey-аккаунтов удалена из UI. В свёрнутом отдельном сценарии оставлены вход и восстановление существующего аккаунта, затем привязка Google/email с серверной проверкой владения. Серверная регистрация и прежние credentials не удалены.
- UUID, рейтинг, история и аккаунты не мигрируются и не удаляются. Совпадение email не объединяет аккаунты. Локальный прогресс остаётся на устройстве при входе; это не серверная синхронизация XP между устройствами.
- GET /api/account/me дополнен списком методов только владельца сессии; provider subjects, email и секреты не возвращаются. Новых таблиц и миграций не требуется.

- git diff --check прошёл. Start.bat и docs/PROJECT_REPORT_RU.md сохранили прежние SHA256.
- Локальный браузер: RU/EN, первый экран, 320 px без горизонтального переполнения, явный гостевой выбор, reload, гостевой ник, профиль, отсутствие auth-форм в Leaderboard и переход из рейтинга в профиль.
- Локальный браузер использовал изолированный HTTP-сервер с явно отключённым account service и 503 для рейтинга. Ни аккаунтов, ни рейтинговых строк он не имитировал. Это UI QA, а не проверка Google, Cloudflare D1, DO или WebSocket.

## Ограничения и найденные замечания

- Перед ответом API экран аккаунта/рейтинга кратко показывает гостевые подписи даже авторизованному игроку, одновременно с текстом проверки входа; после загрузки состояние правильное. Косметическое замечание, изменения опубликованного кода не выполнялись.
- Оболочка продолжает показывать v2.0 вместо 2.1. Это подпись интерфейса, а не признак старого JS.
- Полные рейтинговые матчи проверены в Classic; полноценные Blitz/Chaos/Last One Standing с авторизованными участниками ещё требуют отдельного ручного QA.
- Не проверены физические Android/iPhone, joystick + Dash + ability, смена сети авторизованного браузера, FPS/память длительного Overdrive, restart DO и принудительный сбой outbox/D1 в staging.
- Email не готов до настройки и проверки Resend. Другой Google-аккаунт и новое устройство в этом проходе не использовались.
- Никаких фиктивных результатов, SQL INSERT/UPDATE, удалённых миграций, новых ресурсов, secrets, production deployment, commit, push или merge в этом проходе нет. D1 QA запросы только SELECT; результаты записала игра.

Вердикт: GO для продолжения ограниченного staging QA. NO-GO для публичного production-релиза до закрытия перечисленных проверок устройств, остальных режимов и аварийной доставки. Основной путь Google → настоящий Online-матч → D1 → Leaderboard после reload подтверждён.
