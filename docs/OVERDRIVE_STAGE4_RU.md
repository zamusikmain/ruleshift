## B. Награды и антифарм

Существующие Near Miss (20 × boost), чистое завершение события и серия ×1..5 сохранены. Near Miss вне Daily теперь требует фактического движения не менее 12 px/s, а Online дополнительно проверяет свежий input, connected и намеренное направление. Offline проверяет ввод игрока. Само притяжение/отталкивание без ввода не даёт Near Miss. Существующая дедупликация по угрозе сохранена. Затронутая старая проверка теперь задаёт движение явно; утверждения об одном начислении и отсутствии награды при столкновении сохранены.

Новый Perfect Dodge за точный манёвр, отдельные Risk Zones, Bonus Rush и Clutch Save **не реализованы**. Старый Perfect означает чистое завершение правила, не новую механику Perfect Dodge. Новые XP/ачивки/награды для них не выдаются. Защита старых результатов/Rematch проверяется существующими тестами; полноценный защищённый рейтинг ещё отсутствует.

## D. Управление

- При coarse pointer начальный режим сенсорный; touch pointer переключает на touch, мышь/клавиатура — обратно. Ширина экрана не определяет тип ввода. В клавиатурном режиме джойстик и сенсорные кнопки скрыты. Подсказки WASD/стрелки, Space, E есть в настройках; cooldown/Shield/boost остаются в компактном статусе.
- Fixed сохраняет базу. Floating создаётся первым touch в нижней левой части игровой области, фиксирует центр на всё касание и скрывается при отпускании. Центр ограничен краями разрешённой области. Интерфейсные кнопки/поля/overlay исключены из начала Floating.
- У джойстика один pointerId; Dash и Pulse не перехватывают его. pointerup/cancel/lost capture, blur, visibility, resize и изменение настроек освобождают движение и capture.
- Настройки fixed/floating, чувствительность .5..1.5 и dead zone .05.. .4 сохраняются в `ruleshift.controls.v2`. Размер Small/Medium/Large остаётся в старом `ruleshift.controls.v1`; старое сохранение не перезаписывается. Плавный ползунок размера не добавлен.
- Предпросмотр интерактивный, показывает размер и поведение выбранного типа. Исправлено старое `pointer-events:none`, которое иначе блокировало бы предпросмотр.
- RU/EN добавлены. Существующие safe-area/портретные CSS сохранены, но полноценная проверка телефона/планшета и 320 px ещё нужна. Online portrait rotation gate пока сохранён: поддержку Online portrait нельзя объявлять завершённой.

## E. Глобальный рейтинг: что подготовлено, что отсутствует

Passkeys + одноразовые recovery codes без обязательного email согласованы пользователем. Не введён фиктивный accountId из ника или localStorage-токен для якобы безопасного входа.

Подготовлена первая **неприменённая** SQL-миграция: accounts, credentials, sessions (хеш токена), auth_challenges, recovery_codes (хеш), seasons, matches, participants, ratings, settlement_ledger, pair_history. Нет seed игроков, результатов или глобального рейтинга. UNIQUE ledger, FK и индекс top проверены на отдельной in-memory SQLite. Это локальный SQLite-тест, не D1 runtime integration.

Кандидат парного Elo реализован отдельно: начальное значение 1000 планируется в schema; K=24/(n−1), ожидаемый результат Elo с делителем 400, коэффициент размера .5 для 2 до 1 для 8. По одной паре за серверные 24 часа веса 1, .5, .25, затем 0. Дельты нулевой суммы; без нижнего clamp. Forfeit ниже закончившего, равные места дают .5. Сервер должен передавать реальные места: нельзя выдумывать места 2–8 в last-alive. Функция проверяет 2–8 уникальных IDs, конечные рейтинги/валидные места и историю пар. Она **не подключена к Room**, не подтверждает аккаунты, не хранит историю и не начисляет очки. Остальные свойства anti-abuse/сезонов не объявляются реализованными.

Отсутствуют: WebAuthn verification и onboarding/recovery/delete account; привязка verified account к участнику; durable outbox/alarm; settlement coordinator с атомарным D1 batch; API top-100/me/seasons; загрузка/ошибка/обновление реального рейтинга; тесты полного settlement после перезапуска. UI по-прежнему показывает отсутствие подключения. Leaderboard **не готов**.

Cloudflare D1 `batch()` поддерживает rollback серии при ошибке ([официальная документация](https://developers.cloudflare.com/d1/worker-api/d1-database/)); DO alarms подходят для повторных попыток доставки ([документация](https://developers.cloudflare.com/durable-objects/api/alarms/)). Это проверка предлагаемой архитектуры, не доказательство работоспособности ещё отсутствующего outbox. SQLite-тест rollback использует SQLite transaction, а не подменяет проверку D1.

Текущий `wrangler.staging.jsonc` намеренно **не изменён**, содержит только собственные ROOMS/ASSETS. Подготовленная SQL не применяется существующим build/deploy pipeline.

1. Зафиксировать RP ID/allowed origin отдельно для staging и production, правила eligible ranked-комнат, grace архива сезона, retention и удаление аккаунтов. Приватные гостевые комнаты рекомендуется оставить unrated. Смена домена passkeys требует отдельного плана.
2. Создать staging-only D1 и закрытый Rankings Worker/settlement DO, отдельные bindings/секреты auth origins. Production DB/credentials/сессии не использовать.
3. Сделать backup тестовой базы, применить миграцию только с staging config и явным staging DB name после разрешения. Проверить схему/FK/query plans и конкурентные повторные receipts.
4. Развернуть backend с ranked выключенным; проверить passkey/recovery/session revocation/delete account на двух устройствах. Затем включить ограниченный ranked QA, outbox retries, Rematch/reconnect, повторную доставку, сезонную границу и повторное открытие UI.
5. Откат: выключить допуск новых ranked-матчей, продолжить drain существующего outbox совместимым кодом; откатить Worker/assets на проверенную совместимую версию. Не удалять базу, не удалять journal и не применять down migration вслепую. Полный план отката требует готового backend/outbox.

Эти действия не выполнены. Команд с реальными DB IDs или remote migration в этот проход нет.
