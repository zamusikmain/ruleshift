Адрес: https://ruleshift-2-staging.zamusik-play.workers.dev/.

## Подтверждённый вывод

Опубликован **RULESHIFT 2.0 feature build**, protocol v6, а не старая игровая реализация. Активный deployment остался `afa8865d-006d-44ca-b85e-87478c116f39`, версия `e5151660-7b5f-4269-9893-dfafd77dfce1`, 100% traffic, опубликована 2026-10-09 10:46:04 UTC.

Перед исправлением интерфейса текущая ветка `feature/ruleshift-2-chaos-update` была заново собрана. Файлы её сборки совпали с серверными не только именами, но и полными SHA-256. Это исключает старый dist/другую игровую сборку для проверенного deployment. Документация и игнорируемые QA artifacts в dist не входят.

Подтверждены **две проблемы интерфейса**:

1. Устаревшая маркировка: `index.html` показывал `01`, а `src/ui.ts:updateChrome` жёстко задавал `V.1.0`. Эта маркировка оставалась в feature-ветке и закономерно попала в staging. Внутренняя private npm package version `1.0.0` также не служит идентификатором игрового deployment.
2. Кнопки новых режимов использовали общий `.menu-actions` flex-row без переноса. Пять кнопок шириной минимум 155 px плюс интервалы не помещались в панель. На staging при 1280×720 измерены clientWidth панели 758 px и scrollWidth 787 px; первая и последняя кнопки выходили за границы, часть Daily обрезалась. Горизонтальная прокрутка скрывала новые пункты и ухудшала их обнаружение. Это реальный layout bug, не отсутствие режимов в bundle.

## Browser cache и Service Worker

В `src`, `index.html` и опубликованной совпадающей сборке нет регистрации Service Worker/Cache API. В проверенном браузере новые экраны доступны. Подтверждений проблемы HTTP cache нет; менять кеш-заголовки или удалять сохранения для исправления маркировки не требуется.

Состояние браузера пользователя, в котором симптомы отличаются, недоступно. Историческую/стороннюю Service Worker регистрацию на конкретном устройстве нельзя исключить по одному исходному коду. Поэтому утверждать, что именно кеш пользователя является причиной, было бы предположением.

Если на вашем устройстве **нет перечисленных кнопок**, сначала проверьте точный staging hostname, обновите страницу Ctrl+F5 либо откройте URL в приватном окне. В DevTools Network ожидаются файлы из таблицы выше до следующей публикации. Проверка регистраций в Console (только чтение):

```js
navigator.serviceWorker?.getRegistrations().then(items => console.table(items.map(item => ({scope:item.scope,script:item.active?.scriptURL}))));
```

Не удаляйте localStorage профиля для этой диагностики. При отличии assets сохраните их имена и скриншот отсутствующих режимов; это отдельный сценарий устройства, пока не воспроизведённый в проверке.

После отдельного разрешения из текущей feature-ветки, с остановкой при ошибке каждой команды:

```powershell

```
