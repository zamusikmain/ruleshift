# Реальный QA RULESHIFT 2.0 на staging

Статус: staging опубликован 2026-10-09, базовый real HTTP/WebSocket smoke с двумя Node клиентами прошёл (create/join/start/movement/reconnect/leave/winner/Rematch), отказ v5/1008 и чужого Origin/403 подтверждены. Это короткий Classic сценарий. **Полная матрица ниже ещё не выполнена**, физические устройства и разные сети pending. Unit tests/Room simulations не заменяют эти матчи. Основной production URL не используется для создания тестовых комнат.

## Подготовка

- Записать фактический staging URL, Version ID, дату/UTC, устройство/ОС/браузер, сеть, RU/EN, эффекты Low/Medium/High и число участников. Проверить свежую страницу и protocol v6.
- Минимум ПК Chrome/Edge, физический Android Chrome и физический iPhone Safari. Подключить одновременно Wi-Fi и LTE/5G разных операторов; желательно участники в разных сетях. Вкладки одного ПК пригодны для первого smoke, но не проверки мобильного ввода/сетевого разнообразия.
- Профили только тестовые, сохранения staging отдельные. До/после каждого завершения записывать матчи, W/L/D, XP и достижения; не публиковать session tokens. Включить запись экрана для трудных предупреждений; при передаче очистить приватные данные.

Для реального v5 handshake в DevTools Console **только staging** после создания тестовой комнаты (подставить её код; snippet ничего не печатает из welcome):

```js
if (location.origin !== 'https://ruleshift-2-staging.zamusik-play.workers.dev') throw Error('Staging only');
const legacySocket = new WebSocket(`wss://${location.host}/api/rooms/ABC234`);
legacySocket.onopen = () => legacySocket.send(JSON.stringify({type:'hello', protocol:5, name:'Legacy QA', color:0}));
legacySocket.onmessage = event => { const message=JSON.parse(event.data); if(message.type==='error') console.log('legacy error:',message.code); };
legacySocket.onclose = event => console.log('legacy close:',event.code);
```

Заменить `ABC234` реальным staging-кодом. Для проверки пользовательского сообщения нужен клиент v5 или его воспроизводимый UI тест; этот snippet проверяет транспорт/серверный отказ, а не старый интерфейс. При другом фактическом staging URL сначала согласовать адрес, не удалять защиту origin.

## Мобильный ввод и интерфейс

- Настоящие два пальца: джойстик удерживается, вторым нажать Dash многократно; отпускание Dash не отменяет движение. Проверить размеры Small/Medium/Large и live preview.
- Отмена касания: свайп за пределы, системный жест, сворачивание, потеря pointer capture; движение останавливается и следующий touch принимается.
- Поворот во время игры/паузы/результатов; портрет Survival/Daily, landscape остальных режимов, существующая подсказка поворота. Нет зависшего джойстика.
- Узкий viewport 320 px, типичные Android/iPhone, notch/home indicator, раскрытые/скрытые панели браузера: Dash, pause, warnings, результаты и меню доступны, не перекрываются; длинные RU строки прокручиваются.
- RU и EN для меню, всех hazards/комбинаций, errors, результата, XP и профиля. Проверить звук и эффект Low/Medium/High после reload.

## Опасности, темп и длительность

- Все 8: Laser Grid, Death Spin, Meteor Madness, Shockwave, Hunter Swarm, Danger Tiles, Crossfire, Final Collapse. Записать предупреждение → активную фазу → урон/уклонение → очистку. Проверить быстрое пересечение фронта/луча и Dash. Не считать не встретившуюся случайную опасность проверенной; продолжить тесты и вести список покрытия.
- Все 8 разрешённых combos: Zones+Grid, Zones+Spin, Grid+Madness, Grid+Shockwave, Spin+Madness, Spin+Shockwave, Zones+Grid+Madness, Zones+Spin+Shockwave. Отдельно переход к общей безопасной области при краю/сужении и 8 игроках. Столкновения, серверные snapshots и визуальные фазы должны совпадать.
- Classic: постепенное ускорение; Blitz: 90 сек и короткие паузы; Chaos: частые combos; Last One Standing: давление сужения без возрождения. В первые 10 сек уже есть читаемая опасность.
- Полный Offline Blitz до 90 сек и раннее поражение; пауза ≥30 реальных секунд не расходует игровое время. Полный Daily: успех/поражение/повтор без второй награды, RU/EN, история, reload. Два устройства в один UTC-день проверяют одинаковый сценарий; переход UTC-полуночи — новый день, локальные награды без серверной ценности.
- Survival и Chaos ≥30 реальных игровых минут на ПК и слабом телефоне; поражение, результаты, рекорд, достижения, reload. Проверить, что безопасные переходы реально читаемы, а не только существуют в математической модели.

## Производительность и критерии завершения

- По 3 прогона для Low/Medium/High, 8-player Chaos: первые 30 сек и после 15–30 минут. Записывать FPS, p95/max времени кадра, >50 ms кадры, память и визуальные зависания с указанием инструмента. Browser DevTools performance/memory можно использовать на ПК; если на телефоне инструмента нет, записать это, не придумывать числа.
- Рабочая цель: стабильные 60 FPS на ПК и ≥30 FPS на выбранном слабом телефоне, без регулярных >100 ms пауз и нечитаемых предупреждений. Это критерии QA, не уже достигнутые показатели.
- 20 открытий профиля, 5 Rematch, циклы menu/game/results, reload. Сравнить память после GC в одинаковом состоянии, число обработчиков/таймеров через profiler; единичная heap sample не доказывает отсутствие утечки.
- В Bug report: устройство/сеть/режим/участники/Version ID, шаги, ожидаемый/фактический результат, очищенная запись. Не передавать welcome tokens, cookies, Authorization или секреты.
- GO возможен после прохождения матрицы без критических багов: нет рассинхронизации/двойных наград/зависаний комнаты, приемлемый FPS/мультитач, полные Daily/Blitz, подтверждённая изоляция namespace. Внешний QA пока **pending**, прежний NO-GO для публичного production релиза сохраняется.
